POSTGRESQL - SERVIZIO NON REGISTRATO

    Su Windows questo comportamento di solito indica: (a) installazione fatta senza registrare il servizio (scelta “non come service”), (b) errore di registrazione del service durante il setup, oppure (c) stai guardando i servizi a 64 bit vs 32 bit / installazione in un contesto diverso (meno comune). Procedura diretta di diagnosi e ripristino.

    1) Verifica se il servizio esiste davvero (anche se non lo vedi a colpo d’occhio)

    Apri Prompt dei comandi come Amministratore e lancia:

    sc query type= service state= all | findstr /I postgres
]]>

    Se non ritorna nulla, il servizio non è registrato.

    Controlla anche con il nome tipico:

    • postgresql-x64-9.6

    • postgresql-9.6

    • oppure un nome custom scelto in fase di installazione

    sc query postgresql-x64-9.6
]]>

    2) Verifica che il cluster (data directory) esista

    Di default è qualcosa tipo:

    • C:\Program Files\PostgreSQL\9.6\data

    Controlla che contenga postgresql.conf, pg_hba.conf, base\, global\.

    Se la cartella data è vuota o mancante, l’installer potrebbe aver completato i binari ma non inizializzato il cluster.

    3) Registra manualmente il servizio (soluzione pratica più frequente)

    Vai nella cartella bin:

    • C:\Program Files\PostgreSQL\9.6\bin

    Esegui (sempre CMD Admin), adattando percorso e nome servizio:

    cd "C:\Program Files\PostgreSQL\9.6\bin"
pg_ctl register -N "postgresql-x64-9.6" -D "C:\Program Files\PostgreSQL\9.6\data"
]]>

    Poi avvialo:

    net start postgresql-x64-9.6
]]>

    Se parte, lo vedrai in services.msc.

    4) Se il cluster non è inizializzato, inizializzalo e poi registra

    Attenzione: scegli una directory dati (es. C:\PostgreSQL\data96) e un utente con permessi.

    Esempio:

    cd "C:\Program Files\PostgreSQL\9.6\bin"
initdb -D "C:\PostgreSQL\data96" -U postgres -A md5 -E UTF8
pg_ctl register -N "postgresql-x64-9.6" -D "C:\PostgreSQL\data96"
net start postgresql-x64-9.6
]]>

    5) Cause tipiche quando la registrazione fallisce

    A) Mancano permessi / UAC

    La registrazione del servizio richiede elevazione. Lancia tutto da CMD Admin.

    B) Username del servizio o password errata in fase di setup

    Se durante l’installer hai scelto un account Windows specifico per il servizio e le credenziali non sono valide, il service può non crearsi o crearsi e non avviarsi. In quel caso conviene:

    • disinstallare PostgreSQL

    • cancellare la directory data (se non serve)

    • reinstallare scegliendo “Local System” o creando prima l’utente e verificando accesso/permessi sulla directory dati

    C) Antivirus/EDR blocca la creazione del servizio

    Verifica eventi in Event Viewer:

    • Windows Logs → Application

    • Windows Logs → System
      filtra per postgres, pg_ctl, MsiInstaller, Service Control Manager.

    6) Controllo finale rapido

    Dopo l’avvio:

    sc query postgresql-x64-9.6
]]>

    e test porta (default 5432):

    netstat -ano | findstr :5432
]]>
